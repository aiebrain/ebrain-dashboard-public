# Ebrain OS 업무 대시보드

Ebrain OS 업무 대시보드는 1인 사업자, 강사, 콘텐츠 운영자, 커머스 운영자가 매일 처리해야 하는 업무를 한 화면에서 정리하기 위한 브라우저 기반 운영 대시보드 데모입니다.

이 저장소는 외부 배포용으로 정리한 정적 사본입니다. 별도 서버 없이 `index.html`, `app.js`, `styles.css`, `sample-data.json`만으로 실행되며, 데이터는 브라우저 `localStorage`에 저장됩니다.

- 제작자 YouTube: https://example.com/youtube
- 배포 형태: 정적 웹사이트
- 저장 방식: 브라우저 localStorage
- 주요 대상: AI 커머스, 강의 운영, 콘텐츠 제작, 리드/고객 관리, 프로젝트/할일 관리

## 핵심 기능 요약

### 1. 관제판

오늘 봐야 할 업무를 한 화면에 모아 보여주는 메인 화면입니다.

- 미완료 할일 수 확인
- 응답이 필요한 리드 확인
- 제작 중인 콘텐츠 확인
- 주의가 필요한 업무 신호 확인
- 상품, 전환, 리드, 콘텐츠 제작 화면으로 빠른 이동
- 오늘 먼저 처리할 일, 미응답 리드, 다가오는 일정, 콘텐츠 진행 현황 요약

### 2. 상품관리

판매하거나 준비 중인 상품을 관리하는 화면입니다.

- 상품명, 가격, 상태, 판매 흐름 관리
- 판매 준비 상태 확인
- 상품별 메모와 후속 업무 관리
- 커머스 운영자가 상품 단위로 현재 상황을 파악하기 쉽게 구성

### 3. 마켓팅관리 / 광고·전환

광고와 전환 흐름을 관리하는 화면입니다.

- 광고 소재와 캠페인 상태 확인
- 유튜브, 랜딩페이지, 무료자료, 리드, 리타겟팅 흐름 점검
- 전환 병목 구간 확인
- 다음 마케팅 액션 정리

### 4. 아이디어 메모

떠오른 아이디어를 바로 기록하고 실행 후보로 분류하는 화면입니다.

- 아이디어 빠른 입력
- 실행 후보, 보류, 전환 완료 등 상태 관리
- 아이디어를 할일, 콘텐츠, 프로젝트, 강의 운영으로 연결하기 위한 구조
- 단순 메모장이 아니라 실행 전환을 목표로 한 아이디어 파이프라인

### 5. 리드관리

문의와 잠재고객을 관리하는 화면입니다.

- 신규 문의 등록
- 문의 상태 변경
- 담당자, 우선순위, 후속 메모 관리
- 응답 필요 리드 확인
- 문의를 후속 할일로 연결하는 운영 흐름 지원

### 6. 고객관리

고객 또는 문의 데이터를 고객 관점으로 확인하는 화면입니다.

- 고객별 상태 확인
- 문의 이력과 관리 메모 정리
- 고객 관리 우선순위 파악
- 반복 대응이나 후속 관리가 필요한 고객 확인

### 7. 프로젝트관리

할일과 분리된 상위 업무 단위인 프로젝트를 관리합니다.

- 프로젝트명, 책임자, 상태, 우선순위 관리
- 시작일과 목표 완료일 관리
- 목표, 결과물, 성공 기준 정리
- 다음 결정 또는 다음 액션 기록
- 필요할 때만 후속 할일로 연결하는 구조

### 8. 할일관리

매일 실행해야 하는 업무를 관리하는 작업 공간입니다.

- 할일 추가, 수정, 삭제
- 우선순위와 상태 변경
- 담당자, 마감일, 메모 관리
- 미완료/진행중/완료/보류 상태 확인
- 오늘 할 일과 주간 할 일을 빠르게 파악하는 데 초점

### 9. 강의관리

강의 운영을 위한 준비 상태와 자료를 관리합니다.

- 강의명, 주관, 형식, 상태 관리
- 자료 준비, 공지/안내, 오픈일, 진행일 기록
- 다음 할 일과 운영 메모 정리
- 강의별 준비 부족 항목 확인
- 강의 운영자가 여러 강의를 한 화면에서 관리할 수 있도록 구성

### 10. 프로필 이력관리

AI/AX 강의, 저서, 컨설팅, 운영 채널, 자격, 대표 성과를 정리하는 커리어 이력 DB입니다.

- 강의 이력 기록
- 저서, 컨설팅, 운영 채널 이력 관리
- 증빙 링크와 대표 링크 정리
- 프로필, 제안서, 강사 소개 자료에 활용할 이력 정리
- 표 보기와 카드 보기 중심의 관리 구조

### 11. 일정관리

날짜와 시간 기준으로 일정을 관리하는 화면입니다.

- 월간 달력 보기

### 12. 미팅관리

회의와 미팅을 운영 단위로 관리하는 화면입니다.

- 미팅 일정 관리

## 데이터 저장 방식

이 외부 배포본은 서버 없이 브라우저에 저장됩니다. Supabase를 설정하면 같은 데이터를 클라우드 DB에도 자동 저장할 수 있습니다.

- 기본 저장소: browser `localStorage`
- 선택 저장소: Supabase Postgres
- 기본 키: 앱 내부 localStorage key 사용
- Supabase row key: `supabase-config.js`의 `key` 값 사용
- 브라우저를 바꾸면 localStorage 데이터는 별도로 관리됩니다.
- Supabase를 켜면 브라우저가 바뀌어도 같은 DB row에서 데이터를 다시 불러올 수 있습니다.
- 중요한 데이터는 JSON 백업 기능으로도 내보내는 것을 권장합니다.

## Supabase DB 구축 방법

이 공개 사본은 Supabase로 DB 저장까지 가능하도록 준비되어 있습니다.

### 1. Supabase 프로젝트 생성

1. https://supabase.com 에서 새 프로젝트를 만듭니다.
2. 프로젝트의 SQL Editor를 엽니다.
3. 이 저장소의 `supabase-schema.sql` 내용을 그대로 실행합니다.

생성되는 테이블:

- `dashboard_states`: 현재 대시보드 전체 데이터를 JSONB로 저장하는 메인 테이블
- `dashboard_snapshots`: 수동 스냅샷을 저장하는 백업 테이블

### 2. Supabase 설정 입력

`supabase-config.js` 파일을 열고 아래 값을 바꿉니다.

```js
window.EBRAIN_SUPABASE = {
  enabled: true,
  url: 'https://YOUR_PROJECT_REF.supabase.co',
  anonKey: 'YOUR_SUPABASE_ANON_KEY',
  table: 'dashboard_states',
  snapshotTable: 'dashboard_snapshots',
  key: 'public-demo'
};
```

입력 위치:

- `url`: Supabase Project URL
- `anonKey`: Supabase anon public key
- `key`: 이 대시보드가 사용할 저장 행 ID

주의:

- `anon public key`는 브라우저에 노출되는 공개 키입니다.
- `service_role key`는 절대 넣으면 안 됩니다.
- 현재 SQL 정책은 공개 데모용으로 anon 읽기/쓰기를 허용합니다.
- 실제 고객 데이터나 민감 데이터를 운영하려면 Supabase Auth를 붙이고 사용자별 RLS 정책으로 제한해야 합니다.

### 3. 배포

Supabase 설정을 입력한 뒤 GitHub Pages, Vercel, Netlify에 배포하면 됩니다.

동작 방식:

1. 앱이 먼저 브라우저 localStorage를 확인합니다.
2. localStorage가 없으면 Supabase `dashboard_states`에서 데이터를 불러옵니다.
3. 사용자가 데이터를 수정하면 localStorage에 즉시 저장합니다.
4. Supabase 설정이 켜져 있으면 같은 데이터가 Supabase에도 자동 저장됩니다.
5. 설정 화면의 `DB 스냅샷 생성` 버튼을 누르면 `dashboard_snapshots`에 백업 row가 생성됩니다.
